## 摘要
诸如DAM4SAM等高质量层视频对象分割（VOS）跟踪器在准确率排行榜上名列前茅，但它们是在离线条件下衡量的，一次一帧且不设时钟。在每秒30帧的诚实流协议下，若某一帧未能按时完成计算，则输出最后已计算的掩码，此时胜者崩溃：使其准确所需的丰富记忆因过于缓慢而无法跟上，且其输出对对象是否存在一无所知。我们将这两个失败均追溯到同一处，即跟踪器的记忆管道，并为其针对流式场景进行重建。\method{} 通过在模型内进行优化而非附加回退机制，使记忆机制本身以帧率运行，并通过一个单一的学习型存在信号进行管理，该信号决定哪些内容进入记忆、跟踪器回溯多远、何时抑制输出以及何时重新检测。机制分析表明，固定策略为何无法获胜：在对象真正消失时有帮助的控制，在对象仅仅难以看清时却有害，因此选择必须逐帧进行。在四个基准和五个现代基线中，\method{} 是最强的流式跟踪器，在时钟限制下几乎恢复了离线模型的全部准确率，并且在最困难的内容上超过了其所基于的离线模型。

## Abstract
Quality-tier video object segmentation (VOS) trackers such as DAM4SAM top accuracy leaderboards, but they are measured offline, one frame at a time with no clock. Under an honest streaming protocol at 30 frames per second, where a frame that misses its budget is served the last mask already computed, the winner collapses: the rich memory that makes it accurate is too slow to keep up, and what it emits is blind to whether the object is even present. We trace both failures to one place, the tracker's memory pipeline, and rebuild it for streaming. \method{} makes the memory machinery itself run at frame rate through in-model optimization rather than a bolted-on fallback, and governs it with a single learned presence signal that decides what enters memory, how far back the tracker reads, when to withhold output, and when to re-detect. A mechanism analysis shows why a fixed policy cannot win: the control that helps when an object truly disappears is the one that hurts when it is merely hard to see, so the choice must be made per frame. Across four benchmarks and five modern baselines, \method{} is the strongest streaming tracker, recovers nearly all of the offline model's accuracy under the clock, and on the hardest content exceeds the offline model it is built from.

# StreamDAM: Presence-Aware Memory for Real-Time Streaming Video Object Segmentation

## 1. 核心问题与整体含义

**研究动机与背景：**

- 以 **DAM4SAM** 为代表的高质量视频对象分割（VOS）跟踪器，依赖"丰富的记忆库"（memory bank）在离线评测（offline evaluation）中取得顶尖精度。
- 然而，离线评测的设定是"每帧处理完成后再读下一帧"，相当于没有时钟限制。真实部署场景（机器人、AR、视频编辑）存在硬性的**帧时钟**：30 fps 下每帧约 33 ms 必须出结果，超时则输出上次已完成的掩码（零阶保持，zero-order hold）。
- 论文揭示了两个关键现象：
  1. **计算悬崖**：一旦单帧计算成本超过预算（compute-to-budget ratio ρ > 1），跟踪器会持续输出陈旧掩码，流式分数急剧崩塌。
  2. **存在性失明**：质量优先的模型虽然记忆丰富，但输出的掩码对"对象是否真正存在于当前帧"毫无感知。
- 作者的核心论断是：**这两个失败源于同一个根因——记忆管道（memory pipeline）本身**——它既不够快以跟上帧时钟，又无法判断对象的存在状态。因此，解决方案不是"效率优先 vs. 质量优先"的二选一，而是**重建记忆管道本身**。

**整体含义：** 论文提出了一条区别于"蒸馏提速"（效率优先）与"保质量丢时钟"（质量优先）的第三条路径：让记忆机制本身在模型内部达到帧率，并用一个统一的存在信号在逐帧粒度上动态控制记忆行为。

## 2. 方法论

**核心思想：** StreamDAM 在 DAM4SAM（以 SAM2 为基础）之上，从三方面重建记忆管道：

### 2.1 流式化管道（Streaming the Pipeline，Sec. III-C）

三个模型内优化，按构造保证输出**逐位一致（bit-identical）**，不以精度换取速度：

| 优化手段 | 针对的瓶颈 | 效果 |
|---|---|---|
| 用 torch.compile + CUDA-graph 捕获 Hiera 主干 | 编码器（占总延迟 61%，且不随历史长度变化，决定 ρ） | Hiera-L 主干 23.2 ms → ~16.5 ms |
| GPU 驻留掩码、字节打包传输、设备端像素计数，消除主机同步 | CPU 主机路径（numpy + host sync） | 6.3 ms → ~4.4 ms |
| 对 distractor introspection 的连通分量计算设置分辨率上限 `hires_cap=512`，规模从 min(R,s)² 受限 | DRM 高分辨率尾延迟（1080p 下 6–8 ms） | 降至 ~0 ms；尺度不变决策，5/6 序列位一致 |

优化后总延迟从 ~38 ms 降至 p95 < 32 ms，实现 ρ ≤ 1。

### 2.2 存在信号估计（Estimating Presence，Sec. III-D）

- 内置的存在检测（阈值化 object-score logit）在低置信区间（最需要判断的区间）失效。
- 作者添加一个**轻量因果估计器**：GRU 读取跟踪器已计算出的运行时标量（logits、掩码重叠统计、面积比、缺席连续帧数），输出校准后的存在概率：

```
h_t = g_θ(u_t, h_{t−1})
p_t = σ(wᵀh_t + b)
```

- 训练目标为类别平衡的二元交叉熵（式 4），训练数据与评测数据不相交，所有操作阈值仅在训练集上设定。GRU 在 CPU 上运行，占预算极小。

### 2.3 存在信号驱动的记忆控制（Presence-Governed Memory Control，Sec. III-E）

单一信号 \( p_t \) 驱动四个决策（对应式 2 的耦合记忆控制）：

1. **记忆准入（Admission）**：存储条目当且仅当其存在概率超过阈值 τ 时才进入读取集（式 5），替代原有的 `|m_j| > 0` 过滤。
2. **读取窗口（Recency window）**：用滞回机制（hysteresis）在"密集模式"与"稀疏模式"间切换；目标重现后的爆发期保护对已帮助序列的增益。
3. **输出抑制（Output suppression）**：当 \( p_t < θ \) 时输出空掩码，避免幻觉。
4. **重新检测（Re-detection）**：连续 K 帧被抑制后放宽准入条件，打破"自我强化的缺席锁存"。

### 2.4 关键机制分析（Why fixed policy cannot win）

- 图 1 的逐序列分析表明：DAM4SAM 的固定内存策略对部分序列帮助巨大（+62 pt），对另一部分伤害巨大（−76 pt）。

## 3. 实验设计

### 3.1 流式评测协议（Streaming protocol）

- 30 fps 固定时钟；帧 t 在 t/30 秒释放；跟踪器始终处理最新释放帧；超时则输出最近完成的掩码（零阶保持，ZOH），即 VOT 实时协议规则。
- 所有方法共享同一评测框架；统一从第一帧 ground-truth 掩码初始化（公正性修正）；单目标 J&F 精度。
- 每个方法同时报告 **流式分数**（诚实分数）与 **离线分数**（无时钟、oracle 计算），并报告朴素流式 DAM4SAM-L 作为"陈旧复用下界"。

## 6. 主要结论与发现

1. **流式崩溃的真实性**：朴素流式下 DAM4SAM-L 的离线领先优势蒸发，跌至蒸馏效率型跟踪器之下；流式视角而非离线精度才是部署质量级 VOS 的正确视角。
2. **根因定位**：记忆管道同时过慢且缺乏存在感知，是一体两面的问题。
3. **固定策略的失败**：记忆控制（`|m_j| > 0` 存在过滤 + 时间步长 r 的耦合控制）在"真消失"与"难看清"两种情况下的最优设置互斥，必须逐帧决策。
4. **存在信号的有效性**：单个学习的存在信号统一驱动四个记忆决策，是唯一能同时"修复受伤害序列且不破坏受帮助序列"的策略。
5. **综合性能**：StreamDAM 是四基准上最强的流式跟踪器，恢复离线模型约 97% 的精度损失，且在最难内容上超过离线模型本身。

## 7. 优点

- **定位精准**：将所有失败归因于单一记忆管道，从机制层面（而非工程拼凑）解决问题。
- **不牺牲精度的提速**：三处延迟优化均按构造保证输出位一致，而非以精度换速度；速度不触碰精度瓶颈。
- **统一与简洁**：一个存在信号同时服务四个决策，避免了多模块堆叠的复杂度增长。
- **透明确凿的机制分析**：图 1 的逐序列点图直观揭示了固定策略的"帮助/伤害"分裂，论证了逐帧决策的必要性。
- **实验诚实性**：包含负面结果账本、离线/流式/陈旧复用三重边界、种子方差报告、编译彩票披露、未消除的预算超额序列声明，整体可信度高。
- **可复现性考量**：硬件、软件版本、编译守卫、线程数限制均有详细说明。

## 8. 不足与局限

- **编译彩票（compile lottery）**：LVOS 上种子间有 3.5 分的非高斯方差；pinned-cache 是部署补救而非理论证明。
- **残余延迟尾**：VOST 中一个 2560×1920 的超大序列仍超出帧预算，分辨率尾未被完全消除。

- **多目标缺失**：评测仅覆盖单目标精度，多目标流式分割仍为空白。
- **存在头的离线训练依赖**：存在估计器需在 disjoint 数据集上离线训练，且需要 ground-truth 存在标签，训练数据的覆盖与泛化能力决定其上限；论文未提供详细的训练规模、迭代数或数据量信息，**训练时长与成本未披露**。
