## 摘要
通过状态变换追踪物体对于理解真实世界动态至关重要。然而，现有方法计算成本高昂。TubeletGraph 最近展示了令人印象深刻的能力，但其推理成本（在 VOST 上每个物体-帧约 $4.4$ 秒）排除了任何实时部署的可能性。我们观察到 TubeletGraph 的开销源于对输入视频构建时空分割：（1）无论是否发生变换，对每一帧都密集计算实体分割，（2）追踪场景中的每一个实体，其成本随场景复杂度而非感兴趣的变换数量增加。为解决这两个问题，我们提出 FluxGraph，一种反应式变体，利用 SAM2 的内部多掩膜不一致性作为变换检测的轻量级触发器，并消除了追踪给定视频中所有实体的需求。FluxGraph 在 VOST 上比 TubeletGraph 快约 $3.3\times$，同时提高了追踪性能并保持了状态图质量。此外，我们还在 VSCOS、M$^3$-VOS 和 DAVIS17 上观察到一致的加速比 $3.7-10.7\times$，同时保持了性能。代码已公开在 https://github.com/YihongSun/FluxGraph。

## Abstract
Tracking objects through state transformations is essential for understanding real-world dynamics. However, existing methods are computationally expensive. TubeletGraph recently showed impressive capabilities, but its inference cost (~$4.4$ seconds per object-frame on VOST) precludes any real-time deployment possibilities. We observe that TubeletGraph's overhead arises from building a spatiotemporal partition of the input video: (1) entity segmentation is computed densely for every frame regardless of whether a transformation occurs, and (2) every entity in the scene is tracked, scaling cost with scene complexity rather than the number of transformations of interest. To address both, we propose FluxGraph, a reactive variant that uses SAM2's internal multi-mask disagreement as a lightweight trigger for transformation detection, and removes the need for tracking all entities in the given video. FluxGraph is ~$3.3\times$ faster than TubeletGraph on VOST while improving tracking performance and preserving state graph quality. Furthermore, we also observe consistent speedups of $3.7-10.7\times$ across VSCOS, M$^3$-VOS, and DAVIS17 while maintaining performance. Code is publicly available at https://github.com/YihongSun/FluxGraph.

# 论文总结：高效追踪和理解物体变换（Efficient Tracking and Understanding Object Transformations）

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：真实世界中物体经常经历外观急剧变化的状态变换（如苹果被切开、蝴蝶破茧）。现有方法（如 TubeletGraph）虽然能跟踪物体并构建状态图，但计算开销极大，在 VOST 上每个物体‑帧需约 4.4 秒，无法实时部署。
- **根本原因**：TubeletGraph 采用“急切”策略，预先对整个视频进行时空分割——每帧都进行实体分割，并跟踪场景中所有实体。这使得计算成本与视频长度、场景中物体数量成正比，而与实际变换次数无关（大多数帧和区域无变换）。
- **研究意义**：提出一种高效的反应式方法，仅在可能发生变换时进行密集处理，大幅降低推理成本，同时保持甚至提升跟踪与状态图质量，为机器人操作、野生动物监测、视频理解等下游应用提供实时可能性。

## 2. 方法论：核心思想、关键技术细节
- **核心思想**：利用 SAM2 内部的多掩码不一致性作为变换检测的轻量级触发器。SAM2 在跟踪时会生成一个主掩码和两个备用掩码，物体变换后新出现部分常被备用掩码捕获，导致主掩码与备用掩码显著不一致。因此，无需预先遍历整个场景，只需在检测到“不确定性”的区域进行响应式处理。
- **关键技术细节**：
  1. **反应式候选发现（Reactive Candidate Discovery）**  
     - 首先跟踪初始提示物体，获得主轨跡 `P` 以及每帧的两个备用掩码 `m1_s, m2_s`。  
     - 两个启发式跳过无变换帧：  
       * 低备用掩膜不一致：若备用掩码与主掩码 IoU > τ_agree（0.75），表示 SAM2 确定，跳过。  
       * 小残差区域：即使不一致，但差异区域已被现有跟踪片段覆盖，也跳过。  
     - 当两个条件均不满足时，在该帧调用 CropFormer 进行实体分割，并选取与备用掩码重叠且未被已跟踪区域覆盖的实体作为候选。
  2. **候选过滤：反向跟踪（Reverse Tracking）**  
     - 对每个候选向前传播得到候选轨迹，再将其反向传播（从出现帧回到第一帧），计算与原始提示物体轨迹的平均 IoU（S_rev）。  
     - 仅保留 S_rev > τ_rev（0.1）的候选，丢弃无关干扰（如演员的手）。  
     - 此方法替代了 TubeletGraph 中需要额外模型（FC-CLIP）的“邻近性+语义一致性”检查，完全依赖 SAM2 本身，不引入额外模型依赖。
  3. **最终输出**：将保留的候选轨迹与主轨迹合并，并用 VLM 在变换事件处生成状态图（与 TubeletGraph 相同）。
- **优势**：仅在少数帧（有变换信号）进行实体分割，且跟踪对象数量等于检测到的候选数而非场景物体数，大大降低了计算量。

## 6. 主要结论与发现
1. **显著加速**：在 VOST 上 FluxGraph 比 TubeletGraph 快约 **3.3×**（MPS 从 0.23 到 0.75），在 VSCOS、M³‑VOS、DAVIS17 上分别加速 **4.6×、3.7×、10.7×**。  
2. **保持或提升跟踪质量**：在 VOST 上 J 从 50.9 提升到 52.8；在其他数据集上差距小于 0.6 J，无统计显著退化。  
3. **状态图质量**：整体召回率 H 从 6.5 提升到 9.3，结果对象描述准确率 SO 从 72.3 提升到 82.9，归因于更精确的候选区域。  
4. **无变换视频（DAVIS17）**：FluxGraph 仅产生 1.5× SAM2.1 开销，而 TubeletGraph 为 16×，说明反应式机制只在必要帧消耗资源。  
5. **消融结果**：反向跟踪不可或缺，若移除导致 J 下降最多 15 点；反应式发现提供大部分效率提升而几乎不影响精度。

## 7. 优点
- **创新性**：首次利用 SAM2 多掩码不一致作为变换触发信号，设计巧妙且轻量。  
- **效率‑质量权衡优秀**：在没有损失甚至提升性能的情况下，实现了数量级的加速，填补了实时应用的空白。  
- **实用性好**：代码开源，使用与 TubeletGraph 相同的基础模型（SAM2.1、CropFormer、GPT-4.1），替换昂贵组件无需额外训练。  
- **实验覆盖全面**：包括多样本变换、无变换测试、状态图评估，消融实验完整。  
- **反向跟踪替代语义模型**：无需引入 FC‑CLIP 等额外模型，减少依赖并提高效率。

## 8. 不足与局限
- **依赖 SAM2 的多掩码设计**：若未来跟踪器不提供类似备用掩码，该方法将无法直接迁移（论文已承认）。  
- **快速变换的可能漏检**：变换发生极快以至于 SAM2 备用掩码未产生足够不一致时，触发器可能错过该变换，而 TubeletGraph 的穷举分割则能捕获（论文已指出）。  
- **仅支持一阶变换**：继承自 TubeletGraph 的限制，无法处理多步连续变换的复杂依赖。  
- **超参数泛化性风险**：所有阈值从 VOST 验证集调得，尽管在不同数据上效果良好，但未给出严格的跨域调参研究。  
- **精度上限**：在 VSCOS 和 M³‑VOS 上 FluxGraph 的 J 略低于 TubeletGraph（0.6 以内），并非在所有场景中均优于原方法。
